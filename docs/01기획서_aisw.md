## 1. 프로젝트 개요

### 1.1 프로젝트 명칭 및 코드
- **프로젝트 명칭:** ICT CAN (CampusNav) — ICT 폴리텍 대학 교내 자원 관리 및 내비게이션 통합 시스템
- **프로젝트 코드:** CAN-001
- **프로젝트 약칭:** CAN

### 1.2 프로젝트 설명
**ICT CAN**은 ICT 폴리텍대학의 교내 자산(Assets) 8,401개를 통합 관리하고, 학부생·조교·교수·관리자·게스트·외부인 등 6개 역할의 사용자에게 **자산 검색, 예약, 이관 추적, 교수 정보 관리, 층별 내비게이션**을 제공하는 웹 기반 정보시스템이다.

### 1.3 프로젝트 목표 (Business Objectives)

| 목표 | 설명 | 성과 지표 |
|------|------|----------|
| **자산 가시성 강화** | 8,401개 자산을 키워드/카테고리/상태로 검색 가능하게 통합 관리 | 자산 검색 성공률 > 95% |
| **사용 편의성 증대** | 자산 예약, 이관, 내비게이션을 한 플랫폼에서 처리 | 월 활성 사용자 200명 이상 |
| **운영 효율성 개선** | 자산 이관/폐기 프로세스를 디지털화 | 이관 신청~승인 평균 시간 50% 단축 |
| **사용자 경험 최적화** | 역할별 맞춤형 인터페이스 제공 (6개 역할) | 사용자 만족도 > 80% |

## 2. 비즈니스 요구사항 (BRD)

### 2.1 현재 상황 분석

**문제점:**
- 자산 관리가 분산된 엑셀 파일/수기 기록으로 이루어짐
- 자산 위치, 상태, 예약 정보가 실시간으로 동기화되지 않음
- 층별 위치 파악이 어려워 찾는 데 시간 소요
- 자산 이관/폐기 이력 추적 불가

**기대 효과:**
- 중앙 집중식 자산 데이터베이스 구축
- 실시간 자산 상태 조회 및 예약
- 3D 맵 기반 내비게이션으로 위치 파악 용이
- 완전한 감사(Audit) 추적 가능

### 2.2 주요 기능 요구사항

| 기능 그룹 | 기능명 | 담당 역할 | 우선순위 |
|----------|--------|----------|----------|
| **자산 관리** | 자산 검색 (키워드/카테고리/상태) | 학부생, 조교, 게스트 | **높음** |
| | 자산 상세정보 조회 | 학부생, 조교 | 높음 |
| | 자산 예약 | 학부생 | 높음 |
| | 자산 이관 요청/승인 | 학부생, 조교 | 높음 |
| | 자산 폐기 관리 | 관리자 | 중간 |
| **교수 관리** | 교수 정보 조회 | 모든 사용자 | 중간 |
| | 교수 프로필 관리 (교과목/스킬) | 교수 | 중간 |
| **내비게이션** | 층별 맵 조회 | 모든 사용자 | 중간 |
| | 3D 맵 기반 위치 표시 | 모든 사용자 | 중간 |
| | 경로 저장/삭제 | 모든 사용자 | 낮음 |
| **인증** | 로그인/로그아웃 | 모든 사용자 | **높음** |
| | 역할별 권한 제어 | 시스템 | 높음 |

| 요구사항 | 목표값 | 설명 |
|----------|--------|------|
| **성능** | 응답 시간 < 2초 | 자산 검색, 예약 등 일반적인 작업 |

## 3. 프로젝트 범위 (Scope)

### 3.1 포함 범위 (In Scope)

```
✓ 자산 검색 및 조회 (8,401개 자산)
✓ 자산 예약 (중복 방지, 취소)
✓ 자산 이관 요청 및 승인 워크플로우
✓ 자산 폐기 관리
✓ 교수 정보 및 교과목/스킬 관리
✓ 층별 내비게이션 (3D 맵)
✓ 역할별 접근 제어 (6개 역할)
✓ 로그인/로그아웃
✓ 데이터 초기 로드 (mysql에다넣고실행_fixed.sql)
```

### 3.2 제외 범위 (Out of Scope)

```
✗ Google Maps 상세 지도 통합 (플레이스홀더 수준)
✗ 이메일/SMS 알림 시스템
✗ 모바일 앱 (웹 반응형 디자인만)
✗ AI 기반 추천 시스템
✗ 자산 바코드/QR 스캔
✗ 타사 ERP 연동
✗ 국제화 (다국어 지원 제외)
```

### 3.3 경계 정의 (Constraints)

| 제약 사항 | 설명 |
|----------|------|
| **기술 스택 고정** | Java Servlets + JSP, Apache Tomcat 9.x, MySQL 8.x (변경 불가) |
| **개발 환경** | Windows 11, VS Code + Tomcat 로컬 배포 |
| **데이터 관리** | 기존 8,401개 자산 데이터 그대로 사용 |
| **배포 기한** | 2026-07-31 (약 2개월) |
| **예산 제약** | 오픈소스 및 무료 라이선스만 사용 |

## 7. 위험 요소 및 대응 계획 (Risk Management)

### 7.1 위험 분석

| 위험 ID | 위험 요소 | 발생 확률 | 영향도 | 대응 방안 |
|---------|----------|----------|--------|----------|
| **R-001** | 기술 스택 제약 (Servlet/JSP 레거시) | 중간 | 높음 | 아키텍처 설계서에서 패턴 명확화, AI 에이전트 활용 |
| **R-002** | 8,401개 자산 데이터 정합성 | 높음 | 높음 | 초기 데이터 검증, 마이그레이션 스크립트 테스트 |
| **R-003** | 성능 이슈 (동시 100명 사용자) | 중간 | 중간 | 인덱싱, 쿼리 최적화, 캐싱 전략 수립 |
| **R-004** | 보안 취약점 (SQL Injection 등) | 중간 | 높음 | PreparedStatement 필수 사용, 권한 검사 강화 |
| **R-005** | 일정 지연 (설계 단계 오버런) | 낮음 | 높음 | 주간 진행률 검토, 병렬 개발 추진 |
| **R-006** | 테스트 자동화 부재 | 높음 | 중간 | BDD 프레임워크 도입, 테스트 케이스 작성 |

### 7.2 위험 완화 전략

```
R-001: 개발방법론 문서 충실화 → AI 에이전트 활용도 높임
R-002: 데이터 초기화 스크립트(mysql에다넣고실행_fixed.sql) 검증
R-003: 개발 단계에서 성능 테스트 포함
R-004: 코드 리뷰 체크리스트에 보안 항목 추가
R-005: 2주 단위 마일스톤 설정, 조기 경고 시스템
R-006: Phase 3부터 BDD 시나리오 작성 시작
```
