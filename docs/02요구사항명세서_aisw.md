## 1. 요구사항 명세서 개요

### 1.1 목적
본 요구사항 명세서는 CAN(ICT CampusNav) 프로젝트의 모든 기능 및 비기능 요구사항을 상세히 정의하는 문서입니다. 이를 통해:
- 개발팀이 구현 범위를 명확히 이해
- 테스트팀이 검증 기준을 수립
- 사용자가 최종 시스템의 기능을 예측
- 변경 관리의 기준선 설정

### 1.2 적용 범위
- **프로젝트:** ICT CAN (CampusNav)
- **버전:** 1.0 (기획 단계 기반)
- **적용 기간:** 2026-06-01 ~ 2026-07-31 (Phase 1-5)
- **후속 버전:** 2.0 (Phase 6 이후 추가 기능)

### 1.3 관련 문서
- `기획서_aisw.md` — 프로젝트 기획서
- `현황분석서_aisw.md` — 내부 환경 분석
- `환경분석서_aisw.md` — 외부 환경 분석
- `시스템아키텍처설계서_aisw.md` — (Phase 1에서 작성 예정)

## 2. 기능 요구사항

### 2.1 역할별 접근 제어 요구사항

#### **FR-AUTH-001: 사용자 인증 (로그인)**

| 항목 | 내용 |
|------|------|
| **ID** | FR-AUTH-001 |
| **제목** | 사용자 인증 (로그인) |
| **설명** | 사용자는 사용자명(username)과 비밀번호(password)를 입력하여 시스템에 접근합니다. |
| **액터(Actor)** | 모든 사용자 (학부생, 조교, 교수, 관리자, 게스트, 외부인) |
| **선결 조건** | 로그인 페이지 접근 |
| **기본 흐름** | 1. 사용자가 username/password 입력<br/>2. 시스템이 데이터베이스 검증<br/>3. 인증 성공 시 Session 생성 및 역할 저장<br/>4. 역할별 메인 페이지로 이동 |
| **대체 흐름** | - 인증 실패 시 오류 메시지 표시<br/>- 계정 잠금 처리(5회 실패 후) |
| **예외 처리** | - 존재하지 않는 사용자<br/>- 잘못된 비밀번호<br/>- 시스템 오류 |
| **후조건** | 사용자가 로그인되고 Session에 역할 정보 저장 |
| **기술 요구사항** | - HTTPS 필수<br/>- 비밀번호는 bcrypt로 암호화<br/>- 세션 타임아웃: 30분 |
| **우선순위** | 🔴 **높음** (MVP 필수) |
| **상태** | ✓ 완료 (LoginServlet 구현됨) |

| **후조건** | 세션 종료, 로그인 페이지 표시 |

| **우선순위** | 🔴 높음 (MVP 필수) |

#### **FR-AUTH-003: 역할별 권한 제어**

| 항목 | 내용 |
|------|------|
| **ID** | FR-AUTH-003 |
| **제목** | 역할별 권한 제어 (접근 제어 목록 - ACL) |
| **설명** | 각 사용자의 역할(Role)에 따라 접근 가능한 기능을 제한합니다. |
| **액터** | 시스템 (자동 권한 검사) |
| **역할별 권한** | - **학부생:** 자산 검색, 예약, 이관 요청, 내비게이션 조회<br/>- **조교:** 학부생 권한 + 이관 승인, 자산 이력 조회<br/>- **교수:** 교과목/스킬 정보 입력, 자산 검색, 내비게이션<br/>- **관리자:** 전체 자산 관리, 사용자 권한 제어, 폐기 처리<br/>- **게스트:** 자산 검색(읽기 전용), 내비게이션<br/>- **외부인:** 내비게이션만 조회 (게스트 로그인 없이) |
| **기본 흐름** | 1. 사용자가 기능 접근 시도<br/>2. 시스템이 세션의 역할 확인<br/>3. 역할이 해당 기능 접근 권한 가지면 진행<br/>4. 권한 없으면 접근 거부 메시지 표시 |
| **예외 처리** | 권한 없는 접근 시도 → 403 Forbidden 오류 페이지 표시 |
| **기술 요구사항** | - 모든 요청에서 세션의 role 확인<br/>- @RequireRole 어노테이션 또는 필터 구현 |
| **우선순위** | 🔴 높음 (보안 필수) |
| **상태** | ✓ 기본 구현됨 (강화 필요) |

| **제목** | 자산 검색 |

| **검색 필드** | - **키워드:** 자산명, 설명에 포함된 텍스트 검색<br/>- **카테고리:** 카테고리 선택 (드롭다운)<br/>- **상태:** 사용 가능, 예약됨, 정지됨, 폐기됨<br/>- **위치:** 건물, 층 선택 |
| **기본 흐름** | 1. 검색 페이지(searchAssets.jsp) 접근<br/>2. 검색 조건 입력 (선택사항)<br/>3. "검색" 버튼 클릭<br/>4. SearchServlet에서 데이터베이스 조회<br/>5. 검색 결과 목록 표시 (페이지네이션 포함)<br/>6. 자산 선택 시 상세정보 페이지로 이동 |
| **검색 조건 조합** | - 키워드 + 카테고리<br/>- 키워드 + 상태<br/>- 카테고리 + 위치<br/>- 모든 필드 조합 가능 |
| **결과 표시** | - 자산 목록 (썸네일, 이름, 상태, 위치)<br/>- 페이지당 20개, 페이지네이션 지원<br/>- 정렬: 최신순, 이름순, 상태순 |
| **성능 요구사항** | - 응답 시간 < 2초 (100개 결과 기준)<br/>- 동시 100명 사용자 지원 |
| **기술 요구사항** | - SQL: LIKE, WHERE, JOIN 활용<br/>- 인덱싱: asset_id, category, status<br/>- 입력 검증: SQL Injection 방지 (PreparedStatement) |
| **우선순위** | 🔴 높음 (MVP 필수) |
| **상태** | ✓ 완료 (SearchServlet 구현됨) |

| **예약 (Reservation)** | 자산을 특정 기간 사용하기 위해 사전 등록 | "2026-06-15 10:00~12:00 현미경 예약" |
| **이관 (Transfer)** | 자산의 위치/소유권을 변경하는 프로세스 | "1층 실습실 → 3층 연구실로 이관" |
| **권한 (Role/Permission)** | 사용자가 접근 가능한 기능의 범위 | "학부생은 예약만 가능, 관리자는 모든 기능 가능" |
| **감사 로그 (Audit Log)** | 모든 주요 작업의 시간, 사용자, 내용을 기록한 로그 | "2026-06-01 10:30, user_id=123, 자산 ID 456 수정" |
| **세션 (Session)** | 사용자 로그인부터 로그아웃까지의 상태 | "세션 타임아웃: 30분" |
