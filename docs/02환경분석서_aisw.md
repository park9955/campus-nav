## 2. 비즈니스 환경 분석

### 2.1 교육 기관의 디지털 전환 동향

**국내 대학 및 폴리텍 현황 (2024-2026):**

| 동향 | 현황 | 영향도 |
|------|------|--------|
| **캠퍼스 자산 관리 디지털화** | 80% 이상의 대학이 자산 관리 시스템 도입 중 | 🟠 높음 |
| **학생 생활 서비스 통합** | 다양한 통합 플랫폼 증가 (포탈, 모바일 앱) | 🟠 높음 |
| **실시간 정보 제공 요구** | QR 코드, GPS 기반 위치 서비스 기대 | 🟠 높음 |
| **클라우드 기반 인프라** | AWS, Azure 기반 교육 클라우드 확산 | 🟡 중간 |
| **데이터 개인정보보호** | PIPA(개인정보보호법) 강화 | 🟠 높음 |

**ICT 폴리텍 특수성:**
- **학생 규모:** 약 1,500-2,000명 (중규모 교육기관)
- **자산 규모:** 8,401개 (제조, 정보통신 관련 실습 장비 다수)
- **기술 기관:** IT 및 제조 교육 중심 → 기술 수용도 높음
- **운영 특성:** 학기 중 집중 사용, 여름/겨울 방학 활용 저조

**기대 효과:**
- 자산 관리 비용 30-40% 감소
- 자산 활용률 20% 향상
- 학생 만족도 15-20% 증가

### 2.2 교육부 정책 및 지원 방향

**정부 지원 프로그램 (2024-2026):**

| 프로그램 | 내용 | CAN과의 연계도 |
|---------|------|--------------|
| **디지털 혁신 사업** | 교육기관 디지털화 지원 (예산 제공) | 🟢 높음 |
| **스마트 캠퍼스 사업** | 지능형 캠퍼스 인프라 구축 지원 | 🟢 높음 |
| **산학협력 활성화** | 기업-학교 협력 프로젝트 지원 | 🟡 중간 |
| **개인정보보호 강화** | PIPA 준수 지원 | 🟠 높음 |
| **오픈소스 활용 촉진** | 공공기관 오픈소스 도입 권장 | 🟢 높음 |

**정책 시사점:**
- ✓ CAN 프로젝트는 "디지털 혁신 사업" 범주에 부합 가능
- ✓ 오픈소스 기반 구축으로 정부 정책과 일치
- ✓ 향후 클라우드 인프라로 확장 시 정부 지원 대상 가능

### 2.3 사용자 니즈 변화 (학생 세대)

**Gen Z(2000년대 중반 출생) 특성:**

**CAN 프로젝트 반영 사항:**

- ✓ 3D 맵 기반 시각적 인터페이스 (직관적)
- ✓ 실시간 자산 검색 및 예약
- ⚠ HTTPS, 암호화 필수
- ⚠ 개인정보 최소화 수집

## 3. 유사 시스템 사례 분석

### 3.1 국내 유사 시스템 사례

#### **Case 1: 대학 자산 관리 시스템 (S 대학교)**

**시스템 개요:**
- **구축 시기:** 2022-2023년
- **기술 스택:** Java Spring Boot + React + PostgreSQL
- **사용자 수:** 약 2,000명
- **자산 규모:** 약 5,000개

**주요 기능:**
- ✓ 자산 검색 (키워드, 카테고리, 위치)
- ✓ 자산 예약 (달력 기반)
- ✓ 모바일 앱 제공 (iOS/Android)
- ✓ QR 코드 스캔 기반 자산 추적
- ✓ 대시보드 (부서별, 자산별 통계)
- ✓ REST API 제공 (외부 연계)

**성공 요인:**
- 사용자 교육 프로그램 (3회 이상)
- 단계적 도입 (파일럿 → 전사)
- 지속적 개선 (사용자 피드백 반영)
- 모바일 지원 (높은 채택률)

**교훈:**
- 🟠 초기 단계에서 모바일 앱 지원이 높은 채택률 만듦
- 🟠 QR 코드 스캔은 사용성 향상에 매우 효과적
- 🟠 REST API 제공으로 외부 시스템 연계 가능
- ⚠ CAN은 초기에 웹만 지원 → 향후 모바일 앱 계획 필요

#### **Case 2: 폴리텍 시설 관리 시스템 (D 폴리텍)**

**시스템 개요:**
- **구축 시기:** 2023-2024년
- **기술 스택:** Node.js + Vue.js + MongoDB
- **사용자 수:** 약 1,500명
- **자산 규모:** 약 8,000개

**주요 기능:**
- ✓ 자산 검색 및 조회
- ✓ 예약 시스템 (중복 방지)
- ✓ 층별 맵 (2D 정적 이미지)
- ✓ 모바일 웹 반응형
- ✗ 3D 맵 미제공
- ✗ 교수 정보 관리 미지원

**성공 요인:**
- 기존 시설팀 업무 프로세스와 통합
- 간단하고 직관적인 UI
- 빠른 응답 시간 (< 1초)

**교훈:**
- 🟢 CAN의 3D 맵 기능은 차별화 가능 (경쟁 우위)
- 🟠 단순한 2D 맵도 실용적 (완성도 선택 문제)
- 🟡 교수 정보 관리 기능은 차별화 요소
- ✓ 기존 운영 프로세스와 통합이 중요

#### **Case 3: 스마트 캠퍼스 시스템 (P 대학교)**

**시스템 개요:**
- **구축 시기:** 2024년
- **기술 스택:** Python/FastAPI + React + PostgreSQL + Redis (캐싱)
- **사용자 수:** 약 3,000명
- **자산 규모:** 약 10,000개

**주요 기능:**
- ✓ 자산 관리 (전사적 통합)
- ✓ 3D 맵 기반 내비게이션 (실시간 업데이트)
- ✓ AI 기반 추천 시스템 (자산 이용 패턴 분석)
- ✓ 실시간 알림 (이메일, SMS, 푸시)
- ✓ 빅데이터 대시보드 (의사결정 지원)
- ✓ REST API + GraphQL

**성공 요인:**
- 고급 기술 적용으로 경쟁력 확보
- 사용자 경험 최적화 (AI 추천)
- 실시간 알림으로 사용 활성화

**교훈:**
- 🔴 고급 기술 적용은 높은 유지보수 비용 초래
- 🟠 CAN의 기술 스택 제약(Servlet/JSP)과 비교하면 확장성 한계
- 🟡 향후 단계에서 AI 추천, 실시간 알림 고려 가능
- ✓ MVP에서는 핵심 기능에 집중, 고급 기능은 Phase 2 이후

**향후 인프라 개선 방향 (Phase 6 이후):**
```
선택지 1: AWS Elastic Beanstalk
  - 자동 스케일링, 로드 밸런싱
  - 비용: 월 $20-50 예상

선택지 2: Azure App Service

   - Redis 캐싱 도입

3. 고급 보안
   - PIPA 완전 준수
   - 정적 분석 도구 도입
```

**장기 (2027년 이후):**
```
1. 기술 현대화
   - Spring Boot 마이그레이션 검토
   - 클라우드 전환 검토

2. AI 통합
   - 챗봇 기반 자산 검색
   - 패턴 분석 및 추천

3. 생태계 확대
   - REST API 기반 외부 연계
   - 모바일 네이티브 앱
   - 타사 통합 플랫폼
```

### 9.3 성공을 위한 외부 환경 대응 전략

| **유사 시스템 사례** | 벤치마킹 → 3D 맵 고도화 우선 | 개발팀 |

## 10. 부록: 외부 환경 분석 체크리스트

### 10.1 정기 모니터링 항목

**분기별 점검:**
- [ ] 정부 정책 변화 (교육부 공고)
- [ ] 경쟁 제품 기능 업데이트
- [ ] 보안 위협 (CVE, 취약점)
- [ ] 기술 트렌드 (Stack Overflow, GitHub Trends)

**연간 점검:**
- [ ] 라이선스 준수 (오픈소스 라이선스 변화)
- [ ] 기술 스택 EOL (End of Life) 일정
- [ ] 마이그레이션 필요성 평가
- [ ] 사용자 만족도 조사

### 10.2 의사결정 기준

**외부 환경 변화에 따른 스코프 조정:**

```
신규 기능 추가 의사결정 기준:

1. 정부 정책이나 규제 요구사항 → 우선순위 UP
   예: PIPA 개정 → 즉시 반영

2. 경쟁 제품의 혁신 기능 → 평가 후 결정
   예: 3D 맵 → 이미 진행 중

3. 사용자 요청 → 피드백 수집 후 검토
   예: 모바일 앱 → 운영 후 사용자 피드백 수집

4. 기술 진화 (AI, 클라우드) → 중기 계획에 반영
   예: AI 추천 → 2027년 Phase 6+ 검토

의사결정 원칙:
- MVP 완성이 최우선 (2026년 7월 배포)
- MVP 후 추가 기능은 사용자 피드백 기반
```
